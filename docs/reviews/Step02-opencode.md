## Design decisions and rule mapping

### Money (`lib/finance/money.ts`)
- Branded `Cents = number & { __brand: "Cents" }` prevents accidental mixing
  with arbitrary numbers at compile time; runtime is a plain safe integer.
- `parseEur` does integer arithmetic only (parseInt + *100), never
  `parseFloat`/`*100`. Supports comma or dot separator, leading sign,
  whitespace. Rejects ambiguous grouping (`"1.234"`, `"1,234"`) explicitly
  rather than guessing thousands; documented in `docs/finance-api.md`.
- Rejects exponent notation, excess precision (>2 decimals), non-finite,
  empty, non-string. `-0.00` normalizes to `+0`.
- Bounds: `MAX_SAFE_INTEGER` / `MIN_SAFE_INTEGER`; checked add/sub/sum throw
  `CentsError` on overflow/underflow.

### Settlements (`lib/finance/settlements.ts`)
- Planned amount is immutable; only the settlements array grows.
- `computePaid` = sum(active) - sum(reversed) so a reversal restores remaining
  (compensating entries, per `docs/financial-rules.md`).
- `settlePayment` returns a discriminated union: `{ ok: true, settlements,
  paid, remaining, state }` or `{ ok: false, settlements (unchanged), reason }`.
- Rejects overpayment (paidAfter > planned), zero and negative payments, and
  non-integer payments. Never zeroes the original plan.
- `SettlementStatus` derived: Unpaid (paid <= 0), Partial (0 < paid < planned),
  Paid (paid >= planned).

### Forecast (`lib/finance/forecast.ts`)
- Formulas exactly per `docs/financial-rules.md`:
  - projected = B + I - E - R - S
  - cash-backed = B - E - R - S
- `OrdinaryExpense` and `ReservedCommitment` are distinct types; a linked
  reserve counted in R is never also in E.
- Duplicate IDs collapsed to the maximum unpaid/outstanding per id (Map by
  id, keep max) so presentations/retries cannot double-count. This covers
  duplicate ordinary IDs, duplicate reserve IDs, and linked reserve
  presentations.
- `setupIncomplete` = no balances OR null savings target. Explicit zero
  balance / zero target is NOT incomplete. Incomplete results carry the
  aggregate sub-totals (B, I, E, R) but null projected/cash-backed/shortfall.
- Negative results returned signed; `shortfall` is the negative projected
  value or null when non-negative. Never clamped.
- `hasPendingIncomeCaveat` = remaining income > 0 (expected income is not
  cash).
- Internal transfers are metadata only (net-zero by construction); total B
  already reflects post-transfer balances, so the forecast is invariant.
- Due dates do not release reserved money — R stays protected (no date logic
  in this pure core; date conventions documented in `docs/finance-api.md`).
