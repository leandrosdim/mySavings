## Dependency decisions and versions

Baseline verified against `docs/dependency-review.md` (2026-09-19) and live
npm registry during this run.

Pinned exactly:
- `next` 16.3.5 (stable, not 16.4 canary)
- `eslint-config-next` 16.3.5
- `react` / `react-dom` 19.3.0
- `tailwindcss` / `@tailwindcss/postcss` 4.3.3
- `@types/react` / `@types/react-dom` 19.3.0
- `@types/node` 26.6.2
- `typescript` 5.9.3 (supported stable; 7.x is too new for the ecosystem)

Adjusted from the original prompt baseline:
- `eslint` pinned to **9.39.5** (not 10.11.0). Rationale: `eslint-config-next`
  16.3.5 bundles `eslint-plugin-react@7.37`, which calls
  `contextOrFilename.getFilename` and crashes on ESLint 10 with
  `TypeError: ... getFilename is not a function`. ESLint 9.39.5 satisfies the
  config's peer range `>=9.0.0` and is the latest 9.x line. This is a
  compatibility fix, not a downgrade of a working setup; recorded honestly
  here and not a silent change. npm emits a deprecation notice for eslint
  9.39.5 (end of support line) — noted, not actionable without a compatible
  `eslint-config-next` release for ESLint 10.

No ORM, no auth, no PWA, no DB driver, no external font packages. Minimal
dependency set; 376 packages installed, 0 vulnerabilities.
